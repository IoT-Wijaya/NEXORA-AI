## Project Overview

This is an ESP32-based industrial counter device called "SANDING BESAR" (Sand Grinder Large) built using PlatformIO with Arduino framework. The device counts two types of events: "hasil" (output) and "modal" (input) using physical sensors connected to an ESP32 NodeMCU-32S board with a W5500 Ethernet module and a 20x4 I2C LCD.

This project follows `counter-sanding-kecil` as the gold standard: same directory structure, code style, modularization, naming, and two-core FreeRTOS architecture. Adjustments for the "besar" (large) version are the W5500 Ethernet module (instead of ENC28J60) and the 20x4 LCD (instead of 16x2).

The architecture is divided into two main cores:
- **Core 0**: Sensor task that reads physical inputs and updates counters
- **Core 1**: Network task that handles MQTT communication, LCD display, and counter persistence

## Build and Development Commands

### Building and Upload
- **Build**: `platformio run --target upload` (builds and uploads to device)
- **Build only**: `platformio run` (builds firmware)
- **Upload only**: `platformio upload`
- **Clean build**: `platformio run --target clean`

### Testing
- **Run all tests**: `platformio test` (executes unit tests in native environment)
- **Run specific test**: `platformio test -f test_<component_name>`
- **Run single test**: For individual unit tests, navigate to the specific test directory
- **Test list**: `platformio test --list` (shows available tests)

### PlatformIO Management
- **Initialize**: `platformio init --board nodemcu-32s --framework arduino`
- **Update**: `platformio update` (updates dependencies)
- **Check status**: `platformio status`

### VS Code Integration
- **Open with PlatformIO**: Use the "PlatformIO: Initialize Project" command
- **Debug**: Configure launch.json in .vscode for GDB debugging
- **Code analysis**: Use VS Code's IntelliSense with the provided C/C++ settings

## Code Architecture

### Core Structure
- **src/main.cpp**: Entry point with FreeRTOS tasks setup
- **include/**: Header files with configuration constants and type definitions (`namespace config`, `constexpr`)
- **lib/**: Application-specific libraries, each in its own directory with abstract `I...` interfaces for hardware-dependent parts
- **src/**: Hardware drivers and main.cpp (runs on ESP32)
- **test/**: Unit test directories for each component

### Key Components

#### 1. Configuration Management
- **sanding_config.h**: Main configuration constants (MQTT topics, pin assignments, timing intervals, W5500 pins, LCD 20x4)
- **device_config.h**: Runtime device configuration (MQTT host, user, password, machine name)
- **build_info.h**: Firmware build information (auto-generated by tools/version.py)

#### 2. Hardware Drivers
- **w5500_driver.h**: W5500 Ethernet controller driver (implements INetDriver)
- **i2c_lcd_display.h**: I2C-based 20x4 LCD display driver (implements ILcdDisplay)
- **fixed_mac_source.h**: MAC address source from include/secrets.h (implements IMacSource)
- **esp_spin_lock.h**: ESP32 spin lock mutex (implements ILock)
- **esp_task_watchdog.h**: ESP32 task watchdog wrapper
- **pubsub_mqtt_client.h**: PubSubClient wrapper (implements IMqttClient)
- **nvs_config_store.h**: NVS/Preferences config store (implements IConfigStore)

#### 3. State Management
- **counter_store.h**: Thread-safe counter storage with mutex protection
- **nvs_config_store.h**: Non-volatile storage for persistent configuration

#### 4. Communication
- **pubsub_mqtt_client.h**: MQTT client wrapper
- **net_monitor.h**: Network monitoring (W5500 Ethernet/DHCP)
- **mqtt_service.h**: MQTT service with backoff reconnect and command handling

#### 5. Services
- **console_shell.h**: Serial console command interface
- **sensor_filter.h**: Hardware debounce filtering for sensors
- **lcd_view.h**: LCD display state management
- **command_parser.h**: MQTT command parser

### Task Architecture

#### Sensor Task (Core 0)
- Runs at priority 2
- Reads physical sensors with debounce filtering
- Updates counters when enabled
- Handles local reset button
- Stack: 4KB

#### Network Task (Core 1)
- Runs at priority 1
- Manages MQTT connection and communication
- Controls LCD display updates
- Saves counter to NVS flash
- Coordinates network recovery (W5500 reset after 5 min, restart after 10 min)
- Stack: 12KB

### Network Recovery

If cable is connected but MQTT is not OK:
1. After 5 minutes: W5500 chip reset + DHCP renew
2. After 10 minutes: full ESP.restart() (counter is persisted in NVS)

## Development Guidelines

### Code Style
- Use C++11 features
- Header files use `#pragma once`
- Namespace `config` for configuration constants
- Thread safety using `EspSpinLock` mutexes
- Use `char` arrays and `snprintf`, avoid Arduino `String`
- Document public APIs with Doxygen-style comments
- Write unit tests for each critical component

### File Organization
- **Main**: `src/main.cpp`
- **Config headers**: `include/*.h`
- **Drivers**: `src/*.h` (hardware-specific)
- **App modules**: `lib/<module>/` (`.h` + `.cpp`, `I...` interfaces for hardware)
- **Tests**: `test/<component>/test.cpp`

## Common Development Tasks

### Adding New Sensors
1. Add pin definition to `sanding_config.h`
2. Add initialization in `setup()` in main.cpp
3. Add filtering logic in `sensorTask()`
4. Add tests in `test_sensor_filter/`

### Adding New MQTT Commands
1. Add command enum in `command_parser.h`
2. Add parsing entry in `command_parser.cpp`
3. Add case handling in `handleCommand()` in main.cpp
4. Add tests in `test_command_parser/`

### Debugging
1. Use PlatformIO's monitor: `platformio device monitor`
2. Check serial output at 115200 baud
3. Use `platformio run --target clean` for rebuilds
